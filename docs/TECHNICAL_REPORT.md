# Мастерская блоков — результат технического MVP

Дата: **10 ноября 2026 года**. Статус: **MVP; Android/Yandex QA pending**.

## Результат и границы

Создан отдельный TypeScript/DOM/CSS проект на Vite. Исходная механика сохранена: поле 10×10, 37 форм, три фигуры, preview, одновременные строки/столбцы, исходный scoring/streak/perfect clear, конец партии и новый старт. Phaser не добавлялся. Рабочее имя — «Мастерская блоков» / Block Workshop; финальный бренд не утверждён.

Cozy Gallery не изменён. Актуальный dev совпал с проверенным SHA `da4a7612c870ce75d678b939a491157ae3670883`; финальный git status донора чист. GitHub push, создание PR, merge и публикация в Яндекс Играх не выполнялись. Проект находится в отдельной локальной ветке `mvp/platform`; push в main отсутствует.

Состав сдачи: ZIP исходников, ZIP production dist с index.html в корне, этот отчёт. В проекте есть полный исходный snapshot 10block, исходные тесты, lock baseline, рабочие тесты/CI, notices и проверочный чек-лист. SHA проекта указан в REVISION.txt архива, SHA-256 артефактов — в сопроводительном manifests-файле/приложении к отчёту.

Постоянный hosted URL не опубликован. Браузерная проверка использовала временный управляемый preview; архивы являются самостоятельным проверяемым результатом. Приватная регистрация preview была подготовлена, но синхронизация в main не выполнялась из-за заданного ограничения. Это не релиз и не заявка на модерацию.

## Реализованные подсистемы

| Подсистема | Реализованное поведение |
|---|---|
| Сохранения | Новый `block-workshop:*`; app/schemaVersion/rulesVersion; board/tray IDs/score/streak/rewardUsed; первый набор сохраняется до первого хода. Испорченные размеры, unknown IDs, плохие версии, NaN/Infinity/отрицательные/небезопасные целые отклоняются |
| Язык | RU/EN live без reload; ручной выбор имеет приоритет над SDK; безопасный fallback при storage errors |
| Звук | AudioManager/HtmlAudioOutput/browser lifecycle Cozy; два уровня громкости; mute не стирает уровни; unlock/retry, release media source/Media Session и защита stale callbacks сохранены |
| Пауза | Независимые sdk/browser/manual/startup/ad/transition причины; guard игровых actions, отмена drag с ghost/preview/capture; CSS-анимации и косметический combo countdown приостанавливаются |
| Готовность | SDK bootstrap/listeners до UI/аудио. Ready однократно после готового DOM-кадра и снятия начальной SDK/browser паузы; gameplay marker следует фактическому состоянию |
| Interstitial | Только после подтверждённого New game; cooldown 90 s, retry 15 s, один pending; cover только onOpen; новая партия формируется после close/error без ожидания SDK resume; cover снимается после кадра назначения |
| Rewarded | Подтверждённая замена всего набора один раз за партию. До запроса есть полезный набор с хотя бы одной легальной постановкой. Только onRewarded, безопасное применение после пауз; session/revision/dispose защищают новую партию/выход |
| Standalone | Только точные dev/preview hosts. Дополнительный LAN host разрешается явно в dev через VITE_STANDALONE_HOSTS; в production dev allowlist игнорируется. Web не выдаёт фиктивную награду |
| Упаковка | Без PWA/service worker/внешних fonts/ассетов Cozy. Относительные build paths. SDK /sdk.js предоставляет Yandex. Полные notices включены в dist |

`src/engine.ts`, `pieces.ts`, `board.ts`, `tray.ts`, `layout.ts` побайтно совпадают с выбранным 10block commit. Перечень перенесённых файлов и адаптаций — `docs/PROVENANCE.md`.

## Проверки новой игры

Итоговые числа и размер сборки приведены в приложении к этому отчёту и фактических логах `node22-final-check.log`, `node24-final-check.log`. Проверяются:

- Исходное engine/input поведение, пересекающиеся clears, score и отсутствие ложного game-over.
- Сохранение board/tray/score/streak и первого набора, версия/валидация/изоляция ключей, ограничение reward после reload.
- Один рекламный запрос, close-before-resume/resume-before-close, no-fill/error/throw, до- и после-open watchdog, повторные и поздние callbacks, отсутствие double navigation/cover flash при cooldown.
- Rewarded с/без onRewarded, безопасное staging, сброс/выход/продвижение старой партии.
- Независимые причины паузы, initial pause, ready after frame, отмена ghost/preview на pause/resize/orientation; таймер combo сохраняет остаток.
- Язык и настройки при working/disabled localStorage; mixer pause/retry/dispose и освобождение музыкального источника/Media Session через mocked HTMLAudioElement.
- Production typecheck/build; локальные assets, WAV-заголовки, notices, отсутствие старых storage namespaces/PWA/remote fonts, бюджет dist <5 MiB.

CI на Node 22 содержит эти checks и установку Chromium/production Playwright smoke. **Удалённый GitHub CI не запускался**, потому что push не выполнялся. E2E файлы подготовлены, но не засчитаны в passed unit totals.

## Фактический браузерный QA

Управляемый Chrome в Linux, desktop viewport **1363×936**. Запущена настоящая собранная/исходная DOM-игра, без симуляции игровых кадров:

1. Play, перетаскивание квадрата на поле, счёт **0→4**.
2. Reload: поле/частично использованный tray/счёт **4** восстановились.
3. Settings, RU/EN в текущей партии; позиция и счёт сохранены.
4. Громкость музыки изменена **40→1**, effects оставлены **65**; reload подтвердил эти значения и выбранный RU.
5. Осознанный restart с подтверждением: счёт **4→0**, best **4** сохранён.
6. Исправлено обнаруженное desktop-переполнение после расширения HUD: scrollHeight стал равен viewportHeight **936**, board/tray доступны. Для невысокого landscape добавлена компактная раскладка; её математика проверена отдельно, устройство ещё нужно проверить.

Локальный headless Chromium завершился с `socket() failed: Operation not permitted`. Успех desktop-проверки получен через управляемый preview, а не через успешный запуск локального Playwright suite. Реального Android, физического touch и настоящей рекламы Yandex в этом QA нет. Восстановление звука на аппарате, decode latency и системная media card по mocks не считаются подтверждёнными аппаратно.

## Три недорогих варианта индивидуальности — не внедрены

Оценки инженерные, включают небольшие тесты и QA; ни конверсия, ни retention не измерены.

| Вариант | Что отличает игру | Трудозатраты | Влияние на игру / риск |
|---|---|---:|---|
| Видимый следующий набор | Игрок заранее видит следующие три фигуры и строит план на два набора | 3–5 ч | Меняет решения и глубину планирования без новых правил очистки. Нужны сохранение nextTray и баланс сложности; может сделать игру легче |
| «Ожившая мастерская» | Очищенные линии постепенно собирают небольшую авторскую сцену/предмет на фоне; простая визуальная награда без валюты/магазина | 4–8 ч | Выраженная тема и видимый итог партии; базовая механика почти не меняется. Один лишь reskin не создаёт механическую уникальность |
| Необязательные заказы на партию | Один короткий заказ: очистить две линии одновременно, собрать серию, оставить компактную фигуру пустоты; endless остаётся доступен | 6–10 ч | Даёт игроку цель и меняет приоритеты постановки. Требует отдельного утверждения целей/счёта и проверки, что задания не наказывают за случайную выдачу |

Первый вариант даёт самый дешёвый заметный игровой эффект. Второй — наиболее безопасный для текущего баланса. Третий сильнее выделяет продукт, но требует отдельного решения. Ни одна дополнительная механика не включена самовольно.

Отдельно: облачные сохранения, leaderboard, daily/campaign, детерминированный RNG и метапрогресс не реализованы и не обещаются текущим результатом.
