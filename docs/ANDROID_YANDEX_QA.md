# Обязательный gate: реальный Android и Yandex draft

**Статус: NOT RUN. Реальное устройство и черновик не были доступны в запуске агента.**

Не отправлять на модерацию, пока проверки не пройдены. Оценка — 4–8 активных часов с резервом на исправления, без обещания срока устранения неизвестных дефектов.

## 1. Подготовить сборку и зафиксировать данные

Записать SHA из REVISION.txt/истории проекта, SHA-256 ZIP сборки, модель телефона, Android/Chrome версии, viewport и ориентацию. Основной пользовательский POCO — предпочтительный реальный аппарат.

Для локальной проверки подключить телефон и компьютер к одной сети. Узнать точный LAN IPv4 компьютера (`ipconfig` в Windows). В корне проекта создать `.env.local`, указать, например:

```dotenv
VITE_STANDALONE_HOSTS=192.168.1.5
```

Заменить пример реальным IP. Запустить `npm run dev`. На телефоне открыть `http://<IP>:5173`. Этот exact-host allowlist работает только в Vite dev; production build его игнорирует. Если firewall мешает, разрешить локальный dev port для своей сети. Рекламы и бесплатной эмуляции rewarded здесь нет.

Для настоящей платформы загрузить `block-workshop-mvp-dist.zip` в новый отдельный черновик Яндекс Игр. index.html находится в корне ZIP, `/sdk.js` предоставляет портал. Не использовать ZIP проекта вместо ZIP dist. Включить нужные рекламные форматы в настройках черновика, sticky banners оставить выключенными для текущей компоновки.

## 2. Ввод и партия на физическом телефоне

- [ ] Первый запуск: обучение, Play, звук после первого тапа, музыка и эффекты.
- [ ] Несколько партий: три фигуры, invalid drop, preview, строки/столбцы/пересечения, game-over, restart.
- [ ] Все края и углы поля; нижняя строка с lift 40 px, вертикальные/широкие фигуры.
- [ ] Начать drag → свернуть Chrome → вернуться: ghost/preview исчезли, фигура не потрачена, управление работает.
- [ ] Начать drag → поворот, resize/toolbars: drag отменён, координаты после события правильные.
- [ ] Portrait → landscape → portrait несколько раз; safe areas, нет наложения HUD, все три фигуры доступны.
- [ ] Settings и два slider (музыка/эффекты); потери фокуса/сворачивание не оставляют звук/медиа-карточку.
- [ ] RU/EN: надписи и диалоги переключаются без reload, текущая партия не меняется.
- [ ] Reload до первого хода и после хода: board/tray/score/streak/best/язык/громкость/used reward восстанавливаются.

## 3. Реклама именно в Yandex draft

- [ ] Начальная автоматическая реклама: splash закрывает игровой UI до готовности; нет случайного клика по меню.
- [ ] После 90 s от старта нажать New game → подтвердить; при onOpen включается cover, перед рекламой drag отменяется.
- [ ] После close сразу показана выбранная новая партия, без возврата к старому game-over/подтверждению. Сохранённая SDK-пауза может держать ввод до реального resume.
- [ ] После завершения SDK resume управление/звук возвращаются; нет повторного reset.
- [ ] No-fill/ошибка/частый запрос: без пустой промежуточной сцены и зависшего transition.
- [ ] Добровольный rewarded: согласие → видео → onRewarded → новый полезный набор ровно один раз. Очки/поле сохранены.
- [ ] Простой close/ошибка без onRewarded: исходный набор и доступность награды сохранены.
- [ ] Повторная награда после успешного просмотра недоступна и после reload; бесплатный restart доступен.
- [ ] Реклама + background в обоих порядках: снятие одной причины не включает игру, пока остаётся вторая.
- [ ] Аварийный watchdog не генерирует фиктивный SDK resume. Если SDK остаётся paused, зафиксировать фактический порядок событий, не обходить паузу таймером.
- [ ] В панели SDK проверить LoadingAPI.ready ровно один раз и корректные GameplayAPI.start/stop.

По каждому провалу записать устройство, SHA, последовательность действий, ожидаемый/фактический результат и короткое видео/логи. Модерационный GO возможен только после исправлений и повторного gate.
