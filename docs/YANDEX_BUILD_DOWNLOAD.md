# Как скачать сборку для Яндекс Игр

1. Войдите в GitHub и откройте [Actions → Quality gates and Pages preview](https://github.com/whil3true/block_workshop/actions/workflows/ci.yml).
2. Выберите последний **успешный** запуск для нужной версии:
   - До merge: запуск PR #20 / ветки `feature/yandex-release-monetization-splash`.
   - После merge: запуск `push` ветки `dev`. Сверьте SHA коммита и дату; не скачивайте старый успешный запуск вместо свежего.
3. На странице Summary прокрутите до **Artifacts** и нажмите **yandex-upload-ready**. Такая же ссылка есть в итогах задания `yandex-release`.
4. GitHub скачает **yandex-upload-ready.zip**. Это уже готовый архив: его не нужно распаковывать или упаковывать повторно.
5. Для проверки откройте ZIP в архиваторе без изменения: в корне должны быть `index.html`, `assets/`, `audio/`, `fonts/`, `licenses/` и `THIRD_PARTY_NOTICES.txt`. Папки `dist/` и второго ZIP внутри быть не должно.
6. В консоли разработчика Яндекс Игр откройте нужную игру → **Черновик → Общее → Архив** и загрузите скачанный ZIP целиком. Дождитесь обработки, затем проверьте запуск и настоящую рекламу в черновике. Автоматическая загрузка или отправка на модерацию не выполняется.

## Что проверяет CI

Игра собирается один раз в `build`. Существующий `production-dist` используется браузерными тестами и заданием `yandex-release`. Последнее запускается только после успешных build и всех Chromium/Firefox/WebKit-проверок; sharding Chromium сохранён.

Перед публикацией артефакта проверяются корневой `index.html`, локальные ресурсы HTML/CSS/JS, импорты, шрифты, WAV и растровый манифест с хешами. Запрещены TypeScript, тесты, `node_modules`, `.git`, служебные конфиги, source maps, вложенный ZIP, симлинки, опасные пути, пробелы и не-ASCII имена. Лимит распакованного содержимого — **100 000 000 байт**.

GitHub упаковывает непосредственно содержимое `dist`, а не предварительно созданный ZIP. CI затем скачивает **этот фактический артефакт** через GitHub API, проверяет ZIP/CRC и сверяет каждый путь и каждый байт с протестированным `production-dist`. Число файлов, распакованный размер и SHA-256 ZIP доступны в Summary задания и его логах. Отчёты проверки лежат вне `dist` и в релизный архив не попадают.

`/sdk.js` предоставляет хостинг Яндекса. Локальной заглушки в архиве нет; production JavaScript обязан сохранять официальный путь SDK.

При ошибке обязательных проверок готовый артефакт не публикуется. Скачивайте только артефакт из полностью зелёного запуска, включая `yandex-release`. Если артефакт истёк, запустите workflow вручную для `dev` либо выполните новый запуск PR; не создавайте для этого новый tag или Release.

## GitHub Pages и Яндекс — разные способы проверки

- **GitHub Pages** — существующая standalone-версия из `dev`, обновляющаяся после merge и успешного CI. Настройка публикации не изменена. Официальной рекламы Яндекса там нет; rewarded-награда не имитируется.
- **yandex-upload-ready.zip** — те же production-файлы для размещения в корне хостинга Яндекс Игр. Проверка реального SDK и рекламы выполняется после загрузки в черновик Яндекса.
- **production-dist** — промежуточный артефакт для CI; он появляется раньше завершения браузерных проверок. Для загрузки в Яндекс выбирайте именно **yandex-upload-ready**.

Упаковка не означает прохождение модерации. Чек-лист настоящей рекламы и устройств: [YANDEX_RELEASE_READINESS_AUDIT.md](YANDEX_RELEASE_READINESS_AUDIT.md).

Официальные требования: [загрузка ZIP в Яндекс Игры](https://yandex.ru/dev/games/doc/ru/console/add-new-game.html), [GitHub upload-artifact](https://github.com/actions/upload-artifact/tree/v4).
